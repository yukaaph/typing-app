# 設定確認表 GAS版プロトタイプ

`settings-checklist/`（localStorageのみで動く静的プロトタイプ）と同じ画面・機能を、Google Apps Script（GAS）+ Google Sheetsで動かす版です。認証（ログイン）とデータ保存をSheetsで行います。

## 認証方式：パスワードのみ（ID不要）

SharePointの「パスワード付きリンク共有」と同じ考え方で、**ユーザーIDはなく、パスワードだけでログイン**します。パスワードごとに役割（お客様／社内担当者）と表示名が紐づいており、パスワード自体が「誰か」を判定する鍵になります。

- パスワードは**英数字15桁のランダム文字列**。スプレッドシートのメニュー「設定確認表 管理」から発行できます（`Admin.gs`）。
- 発行時にその場で一度だけ表示されます（Usersシートにはハッシュ化されたものしか残らないため、後から見返すことはできません）。控えてリンクと一緒にお客様へお伝えください。
- 紛失した場合は同じ画面からもう一度発行し直してください（同じ人に対して複数のパスワードが有効な状態でも問題ありません）。

## データの持ち方

- **Users シート**：`passwordHash / role / displayName / createdAt` の4列。ログイン時にパスワードのSHA-256ハッシュをこの表と照合します。IDは持たず、パスワードのハッシュそのものが検索キーです。
- **ContractState シート**：`contractId / stateJson / updatedAt` の3列。契約1件分の設定内容（元プロトタイプの `state` とほぼ同じ形）をJSON文字列としてまるごと1セルに保存します。複数契約に対応した正規化スキーマではなく、デモ用に契約1件（`C-2026-0001`）を共有する前提です（＝どのパスワードでログインしても同じ設定データを見ます）。

## 新しいパスワードの発行方法

1. 上記のSpreadsheetを開く
2. メニュー「設定確認表 管理」→「お客様用パスワードを発行」（または「社内担当者用パスワードを発行」）
3. 表示名（自治体名・担当者名など）を入力
4. 表示されたパスワードを控えて、リンクと一緒にお客様・担当者へ共有する

Apps Scriptエディタから直接発行したい場合は、`Auth.gs` の `issueAccessPassword_(role, displayName)` を呼び出しても同じことができます。

## デプロイ手順（ゼロから構築する場合）

1. **Google Sheetsを新規作成**します（例：「設定確認表_DB」）。
2. そのシートのメニューから **拡張機能 > Apps Script** を開きます（このシートに紐づいたスクリプトプロジェクトが作られます）。
3. エディタで、このフォルダ内の各ファイルと同じ名前・内容のファイルを作成します。
   - `appsscript.json` は、エディタ左の歯車アイコン「プロジェクトの設定」で「`appsscript.json`マニフェストファイルをエディタで表示する」をONにすると編集できるようになります。
   - `.gs` ファイル（`Code.gs` `Auth.gs` `Admin.gs` `DataService.gs` `Api.gs` `Setup.gs`）は「ファイル > 新規 > スクリプト」で作成し、中身をコピーします。
   - `.html` ファイル（`Index.html` `Stylesheet.html` `JavaScriptClient.html`）は「ファイル > 新規 > HTML」で作成し、中身をコピーします（拡張子`.html`は自動で付きます）。
   - `clasp` (`npm install -g @google/clasp`) をお使いの場合は、このフォルダをそのまま `clasp push` していただいても構いません。
4. 関数選択のプルダウンで **`setupSpreadsheet`** を選び、▶実行します。初回は権限の承認を求められるので許可してください。
   - 実行後、シートに `Users` と `ContractState` の2つのタブが作成され、上部メニューに「設定確認表 管理」が追加されます。
   - `Users` シートには、デモパスワード（お客様用: `demoCustomer123`、社内担当者用: `demoStaff123456`）が登録されます。
5. **デプロイ > 新しいデプロイ** を開き、種類で「ウェブアプリ」を選択します。
   - **実行するユーザー**：自分（オーナー）
   - **アクセスできるユーザー**：全員
   - この組み合わせが必要です。「全員」にするのは、お客様が社外の方でGoogleアカウントを持たない前提のためです（ログインはGoogleアカウントではなく、独自のパスワードのみで行います）。
6. デプロイ後に発行される **ウェブアプリのURL**（`.../exec` で終わるURL）を開くと、パスワード入力画面が表示されます。

## 元プロトタイプとの主な違い

- 認証にIDがなく、パスワードのみでログインします（今回追加）。
- ログイン中のロール（お客様／社内担当者）でできることが**サーバー側でも**強制されます（元の静的プロトタイプはブラウザ側のチェックのみでした）。
- 「デモデータをリセット」は、お客様・社内担当者で共有している契約データだけを初期化します。ログイン状態はそのまま維持されます（静的プロトタイプではリセット時にログアウトもしていました）。
- データはブラウザのlocalStorageではなく、Google Sheets上に保存されます。複数人が同時に開いても同じデータを見ます。

## 制限・注意点

- **本番グレードの認証ではありません。** パスワードのハッシュ化はしていますが、ログイン試行制限・多要素認証・監査ログなどはありません（ただしパスワード自体が高エントロピーなランダム15桁なので、人が選ぶパスワードよりは推測されにくい設計です）。実際の顧客データを扱う本番環境では、Google Identity Platform や外部の認証基盤（Auth0, Firebase Authなど）の採用を推奨します。
- 発行したパスワードの平文はどこにも保存されません（発行時に一度だけ画面表示されます）。紛失時は再発行してください。
- 現状は契約データを1件だけ共有する設計です。パスワードごとに別々の契約データを見せたい（自治体ごとにデータを分離したい）場合は、`DataService.gs` のキー付け（今は固定の`DEFAULT_CONTRACT_ID`）を見直す必要があります。ご要望があれば対応します。
- セッションは `CacheService` を使っており、最大6時間で自動的に切れます（Apps Scriptの仕様上の上限です）。
- このリポジトリの環境ではApps Scriptの実行・デプロイができないため（`clasp`を使い一部は自動化しましたが）、**すべての機能を実機で確認できているわけではありません。** エラーが出た場合は、エラーメッセージ（Apps Scriptエディタの「実行数」ログ、またはブラウザのコンソール）を共有してください。
